Privacy policy

SILK HOUSE · last updated 29 September 2026

SILK HOUSE is a desktop application that runs on its operator's own computer. There is no SILK HOUSE server, no account and no shared installation. Nothing described below is sent to the developer, and there is nowhere for it to be sent: the application's only network calls go to the services its operator has configured it to use.

Google user data the application accesses

With the operator's explicit authorization, and only for channels they own or manage:

  • Channel identity — the channel id, title and public subscriber count of the channel chosen at the Google consent screen. This is how the application knows which channel an authorization belongs to.
  • Video upload — videos the operator produced with the application are uploaded to that channel, always privately, and their processing status is read back to confirm the upload succeeded.
  • Channel analytics — views, watch time, retention and similar figures for that channel's own videos, used to show the operator how their published videos are performing.

How it is used and stored

  • Everything is stored in a local SQLite database and local files on the operator's computer, and is used only to display it back to them inside the application.
  • Authorization tokens are kept in the operating system's credential store — Windows Credential Manager, macOS Keychain or the equivalent. They are never written to the project's configuration files, never committed to version control and never printed to logs, which pass through a redaction filter.
  • Google user data is never sold, never shared with anyone, and never used for advertising or for training any model.
  • Google user data is not sent to any of the other services listed below. Those receive only what the operator's own project produces.

Other services the application may call

Each is optional and inert until its credential is configured by the operator. Only the project's own content is sent, never Google user data:

  • An OpenAI-compatible endpoint — topic and script text, for writing and reviewing.
  • Pexels and Pixabay — search terms, for finding stock footage.
  • RunPod — image prompts, when image generation is enabled.

Narration is synthesised locally. No audio ever leaves the machine.

What the application does not collect

There is no telemetry, no usage analytics, no crash reporting and no automatic contact with the developer of any kind.

Retention and removal

  • Data stays on the operator's computer until they delete it. Removing the application's workspace directory removes the database, the media and the produced videos.
  • Access can be withdrawn at any time at myaccount.google.com/permissions, which invalidates the stored authorization immediately.
  • Stored authorizations can also be deleted from the operating system's credential store directly.

Limited Use

SILK HOUSE's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.
